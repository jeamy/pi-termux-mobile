Diese Seite schickt Aufträge an den Koordinator, mit dem das Gerät unter „Spaces“ gekoppelt ist. Ein Auftrag gilt erst als erledigt, wenn der Koordinator sein Ergebnis meldet. Jeder Auftrag hat eine Auftrags-ID; geht die Verbindung verloren, wird mit derselben ID nachgefragt statt neu gestartet.

Hinweise

Warnungen des Koordinators, etwa Hosts ohne Lebenszeichen oder hängende Läufe.

Vorgänge

Die Aufträge, die dieses Gerät gesendet hat, mit ihrem Stand. Ein offener Vorgang kann mit derselben ID erneut abgefragt werden.

Ein Lauf ist eine verteilte Rechenaufgabe, hier das Primzahlsieb. Seine Tasks liegen in den Spaces seiner Members; Worker holen sie dort ab. Pausieren, Fortsetzen und Stoppen wirken auf alle Members gemeinsam und gelten erst, wenn jeder Member bestätigt hat.

Läufe
＋ Neuen Primzahlsieb-Lauf starten

Name des Laufs, frei wählbar und eindeutig. Er beginnt mit einem Buchstaben oder einer Ziffer, danach sind auch . _ : - erlaubt, höchstens 96 Zeichen. Derselbe Name startet keinen zweiten Lauf.

Der Zahlenbereich, der gesiebt wird: von „Von“ bis ausschließlich „Bis“. 1 bis 1001 prüft die Zahlen 1 bis 1000.

Wie viele Zahlen ein Task umfasst (1 bis 4096). Kleinere Blöcke ergeben mehr Tasks und verteilen sich feiner auf die Worker.

Die Spaces, in denen die Tasks des Laufs liegen, durch Komma oder Zeilenumbruch getrennt. Die Liste steht nach dem Start fest.

Ein Worker ist ein Prozess auf einem Host, der Tasks aus einem Space holt und abarbeitet. Eine Zuweisung legt fest, wie viele Worker welcher Art auf welchem Host für welchen Space laufen sollen. Der Host meldet zurück, wie viele tatsächlich laufen.

Zuweisungen
＋ Zuweisung anlegen oder ändern

Frei wählbar. Mit einem vorhandenen Namen wird diese Zuweisung geändert, mit einem neuen wird eine angelegt.

Der Host, auf dem die Worker laufen sollen, mit seiner ID in der Föderation.

Welches Programm der Worker ausführt. Für das Primzahlsieb ist das sieve. Der Host muss diese Art kennen, sonst lehnt er ab.

Der Space, aus dem die Worker ihre Tasks holen, meist ein Member des Laufs.

Bindet die Worker an einen Lauf: Sie nehmen nur dessen Tasks und halten an, wenn er pausiert.

Wie viele Worker laufen sollen (0 bis 64). 0 beendet alle, jeden nach seinem laufenden Task; nichts wird mitten in der Arbeit abgebrochen.

Benannte Spaces auf den Hosts der Föderation anlegen und außer Betrieb nehmen. Der Lebenslauf eines Spaces: aktiv → archiviert → gelöscht. Ein archivierter Space nimmt keine neuen Einträge an und kann reaktiviert werden.

Space anlegen

Der Host, auf dem der Space liegen soll.

Lesbarer Name, nur Kleinbuchstaben, Ziffern und . _ -, höchstens 64 Zeichen. Gibt es den Alias auf dem Host schon, wird der vorhandene Space zurückgegeben statt eines zweiten.

Space ändern

Die feste ID des Spaces, wie sie beim Anlegen gemeldet wurde, nicht der Alias.

Löschen gelingt nur bei einem archivierten, leeren Space, der zu keinem Lauf gehört. Seine ID bleibt danach reserviert.

Deployment

Eine Deployment-Config beschreibt Hosts, Spaces und Worker einer Föderation als JSON (siehe npm run bootstrap in phi-spaces). Keine Geheimnisse einfügen: Schlüssel und Tokens gehören nicht hinein.

Zeigt, welche Schritte nötig wären und ob etwas blockiert. Es wird nichts geändert.

Holt den Stand, den der Koordinator für dieses Deployment zuletzt angewendet hat. Aus der Config wird nur das Feld deployment gelesen.

Audit

Die letzten 50 Admin-Aufträge aller Geräte: was, wann, von wem und mit welchem Ausgang.
